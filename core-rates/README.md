# core-rates — таблица ставок Core (локально, не задеплоено)

- `rates.py` — таблица ставок (объект, вид работ, единица, значение, документ, версия, дата, комплексная строка) и ответ по правилам без LLM.
- Правила: ключ = объект + вид работ + единица; руб/м² и руб/м не смешиваются и не пересчитываются.
- Разные значения с одной последней датой → `conflict`: показываются все версии с документом, выбор за владельцем.
- Одна последняя дата → `ok`, ранние версии упоминаются («Ранее: …»).
- Нет объекта / работ / единицы, неоднозначная единица → `refuse` с причиной (`unknown_object`, `unknown_work`, `unit_mismatch`, `ambiguous_unit`, `no_object`).
- Модель только переформулирует `text` (`ask(q, formulate=...)`); статус и значения она не меняет.
- `sample-rates.json` — синтетические данные (не реальные документы и клиенты): дом 10, террасная доска 3500/4000 руб/м² (две версии акта от 26.08.26, комплексная строка) и 1700/2000 руб/м.
- `eval-set.json` — эталонный набор на реальных ставках (`rates.json`, 17 вопросов, B26 п.1 03.10.2026); `eval-set-sample.json` — прежний синтетический (11 вопросов, для `sample-rates.json` и тестов).
- `run_eval.py` — прогон и метрики (без аргументов — синтетика, `run_eval.py rates.json` — реальный набор):
  `answer_accuracy` (верные ответы), `refusal_accuracy` (верные отказы), `overall`; код выхода 0 только при 100 %.
- Запуск: `python -X utf8 run_eval.py [rates.json] [eval-set.json]`
- Тесты: `python -X utf8 tests/test_rates.py -v`
- Перед любым изменением Core прогонять набор; провал = изменение не принимается.
- Источник реальных ставок — `SOURCES.md`; выгрузка `export_rates.py --db knowledge.sqlite --project "…" --out rates.json` (mode=ro, без ПДн), тесты `tests/test_export.py`; на сервере — `steps/step86-export-rates.sh` (пишет только /tmp).
