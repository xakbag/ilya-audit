## 3. Варианты
| вариант | плюсы | минусы | ресурсы | риск ошибки |
|---|---|---|---|---|
| 1. Таблица фактов + SQL (ставки, обязательства) | точно, объяснимо, конфликты видны, быстро | надо извлечь и нормализовать, покрывает только известные виды фактов | ≈0 (SQLite, CPU) | низкий; ошибка = отказ, не выдумка |
| 2. FTS5/BM25 + русский стеммер (Snowball) или леммы (pymorphy3) | уже есть FTS5, дешёво, точные слова и числа | не понимает синонимы и перефразы | индекс ≈ размер текста (гипотеза: сотни МБ), CPU | средний: находит, но не отвечает |
| 3. Эмбеддинги (bge-m3 / multilingual-e5 через Ollama) + sqlite-vec | смысл, перефразы, переписка | индексация на GPU, хуже на числах и номерах домов | 259 505 × 1024 × 4 Б ≈ 1,06 ГБ (расчёт); модель ≈1–2 ГБ VRAM (гипотеза); Qdrant — +1–2 ГБ RAM (гипотеза) | средний: «похоже» ≠ «верно» |
| 4. Гибрид BM25+вектор (RRF) + реранкер (bge-reranker) | лучшее покрытие для C/D | сложнее, реранкер — ещё GPU | 3 + реранкер ≈1 ГБ VRAM (гипотеза) | средний; снижается порогом отказа |
| 5. «Всё через LLM» (RAG без таблиц) | быстро собрать | путает версии и единицы, выдумывает | GPU на каждый вопрос | высокий для A — **отклонён** |

Выбор: 1 как ядро для A/B/E, 2→4 как поиск для C/D и как источник кандидатов для 1. sqlite-vec вместо Qdrant:
одна база-файл, нет новой службы, памяти WSL хватает (гипотеза, проверить замером на этапе 3).

## 4. Сквозные правила
- **Маршрутизатор** по классам (правила → при «unknown» лёгкая модель qwen3:4b только выбирает класс из списка).
  Неопределённость → отказ, а не угадывание.
- **Контракт ответа** (`infra/search-proto/answer.py`): `status ok|conflict|refuse`, `class`, `reason`,
  `values[]` {value, unit, document, version, date, complex, composition}, `earlier[]` («ранее: …»), `text`.
- **Модель только формулирует.** Проверка: числа нового текста ⊆ числа источников, все значения ответа на месте,
  иначе берётся детерминированный текст (`formulation_rejected`). Для B/C/D — ещё «цитата дословно есть в
  `evidence.text`» (как уже делает Core).
- **Отказ при слабом совпадении**: порог по BM25/косинусу + обязательное совпадение объекта; «частично» = отказ
  с перечнем найденного.
- **Приватность**: переписка и ПДн обрабатываются только локальной Ollama; во FreeLLMAPI — только после
  `infra/gateway-freellm/sanitizer.py` и только белый список моделей (`docs/b24-decision-20261002.md`).
  Чужой текст = данные: при извлечении из переписки снимать zero-width/bidi и HTML-комментарии, «инструкции»
  в сообщениях не исполняются, а помечаются.
- **Режимы GPU**: индексация/эмбеддинги/извлечение обязательств — только в ночном окне или HEAVY; днём (LIGHT)
  только SQL, BM25 и короткая формулировка qwen3:4b; в режиме «Игра» — без модели (контракт уже даёт текст).
