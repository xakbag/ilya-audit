## Топ-2 рекомендации и план пилота

**1. litequeue — ядро оркестратора** (тема 1; CLAUDE.md §7 п.2, до S8).
- Почему: MIT, только stdlib, SQLite; claim-ID + `retry_expired()` закрывают lease/таймаут и «застрявшего воркера» (очередь 140/0 без причины).
- Пилот локально, 4–6 ч, сервер не трогаем: прочитать весь код litequeue и `docs/message_claim_ids.md`; вендорить фиксированный коммит в `infra/orchestrator/`; обёртка `task_state` (blocked_reason ∈ no_executor, quota_exhausted, waiting_night_window, memory_guard, game_mode; attempts/max_attempts → dead); тесты: истёкший lease возвращается, старый claim не меняет задачу, 3 неудачи → dead, blocked всегда с причиной.
- Критерий: тесты зелёные; на копии реестра `assignment-supervisor` (снятой с учётом WAL) каждая задача получает состояние и причину.
- Дальше по «да»: один реальный тип задачи параллельно старой очереди, без отправок наружу. Откат: выключить таймер нового оркестратора.

**2. Gatus — мониторинг по результату** (тема 3; D5, D4, S3).
- Почему: Apache-2.0, один Go-бинарник, YAML ложится в `infra-config/` (S6), задачи сами сообщают о полезном результате, Telegram из коробки, без Docker.
- Пилот 3–5 ч: YAML на 6 проверок — `/health` 8771 (поле mode, свежесть), `status.json` доски (возраст < 5 мин), restic (снапшот < 26 ч, пушит скрипт бэкапа), мост QA (delivered_at < N ч), почасовой аудит (после S3), Core (после S9). Бинарник с релиза GitHub с проверкой sha256, слушать только 127.0.0.1, `MemoryMax=128M`; текст алерта «контур X красный N мин», без ПДн.
- Критерий: на тестовом стенде «старый» status.json → алерт ≤ 10 мин; в норме ноль ложных за сутки.
- Нужно «да»: установка бинарника на сервер (§1), токен бота через EnvironmentFile (как S2).
- Альтернатива без нового ПО: `last_result_at` + Period/Grace и отправка в Telegram прямо в `collector.py` (≈3 ч).
