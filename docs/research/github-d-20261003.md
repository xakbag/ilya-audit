## Топ-3 для пилота

1. **sqlite-vec + bge-m3 + Snowball/pymorphy3 → гибрид в нашем FTS5** (этап 2 B27, классы C/D).
   Взять: код sqlite-vec как расширение с фиксированной версией (после чтения исходника и sha256), bge-m3 через Ollama ночью, нормализацию единиц и лемм.
   Готовность: на eval-наборе классов C/D полнота поиска (нужный документ в топ-5) ≥ 0,9 против FTS5 без морфологии; «кв.м/м²/погонный» находят верную строку (провал B26 = 0/9); индексирование только в окне HEAVY, VRAM днём не растёт.
   Откат: отдельная таблица `chunks_vec`, флаг `SEARCH_VECTOR=0` — поиск только FTS5; удалить таблицу.
2. **langextract (идея и при необходимости код) → таблица фактов из договоров и переписок** (классы A/B/E).
   Взять: схема «факт + точный фрагмент-источник + дата документа», примеры на русском, вызов через наш шлюз (санитайзер fail-closed, Ollama/FreeLLMAPI по белому списку). Конфликт версий — наш SQL: один объект/вид работ/единица, разные значения в разных документах → ответ «конфликт» с обеими цитатами.
   Готовность: на 20 размеченных вручную документах точность извлечения цифр ≥ 0,95, у каждого факта есть фрагмент-источник, совпадающий с текстом дословно; ни одного факта без источника в таблице.
   Откат: факты пишутся в отдельную таблицу с `extractor_version`; удалить версию — Core работает как сейчас (rates.py).
3. **kotaemon / AnythingLLM — только как эталон интерфейса ответа** (без установки на сервер).
   Взять идею: ответ → список цитат с превью куска (файл, лист, строка), подсветка числа. Перенести в вкладку «Спросить» доски и в контракт ответа B27.
   Готовность: каждый ответ на доске показывает ≥1 источник с местом; при конфликте — обе версии рядом; на «не знаю» источников нет и это явно сказано.
   Откат: прежний вид вкладки (`*.old-*` на хостинге, как в B25).

Не брать сейчас: RAGFlow, Onyx, PrivateGPT (память/VRAM), LightRAG/GraphRAG (LLM на каждом куске), pandas-ai (исполнение кода моделью), Khoj (AGPL). paperless-ngx — отдельное решение Ильи, если понадобится архив сканов с OCR; на QA не влияет.
