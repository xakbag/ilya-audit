# Core: как вопрос превращается в ответ (B26, 02.10.2026, только чтение)

Источники: `evidence/b26-r1…r4-*.txt` (юниты, код), `evidence/b26-e1/e2-*.txt` (прогон), `evidence/b26-summary-20261002.txt`.

## Цепочка
```
ярлык «Открыть ILYA CORE» → POST /api/session {token} → кука core_session
  (или служебно: Authorization: Bearer <access-token>, так ходят quality30/continuous_quality)
→ smart-core :8767 (core/app/core.py, 319 стр., User=smart-core)
   POST /api/tasks → tasks.sqlite (queued) → worker() → resolve_context()
     • объект угадывается только по словам «Сколково / Одинцово / Переделкино»
     • дом — по «дом 10», «10-й дом»; контекст беседы 30 дней
   execute(): финансовые слова → /api/search + «financial_guard» (суммы не считает)
              иначе → GET smart-knowledge :8765 /api/ask
→ smart-knowledge (apps/knowledge.py, User=smart-reader, catalog/knowledge.sqlite ro)
   1. несколько домов в вопросе → «уточни»
   2. contract_answers: цена договора / продавец / покупатель (Договоры_с_покупателем)
   3. structured_rates.lookup_work_rates + work_prices: строки актов з/п (.xls/.xlsx),
      колонки B..F, единица (м2/м3), этаж, «комплексная строка» → verified_act_columns
   4. иначе FTS5 поиск (259 509 фрагментов, 6 539 документов)
      all_terms → локальная модель через шлюз :8771 с проверкой цитат и чисел
      some_terms → Core заменяет ответ на «найдены только частичные совпадения»
→ Core проверяет: проект источников, цитаты дословно; пишет result в tasks.sqlite
```
smart-map :8766 (gunicorn, /login) — доска связей, в цепочку ответа не входит.
messenger-context — отдельные воркеры (structure/semantic), Core их код не вызывает;
но сообщения уже лежат в knowledge.sqlite как документы `chat_message` 4 826,
`chat_attachment` 699, `chat_task_candidate` 303 (задачи из чатов: 303, все `needs_review`).

## Что умеет (факт по прогону)
- Ставка по актам з/п для проекта + дома + «м²/м2», с источником (файл, лист, строка) и
  пометкой «комплексная строка». Дом 10, террасная доска, м²: в ответе есть 4 000 и 3 500
  и дата 26.08.26, но также строка 28.07.26 и **нет явной пометки «две версии»**.
- Цена договора / стороны договора (не прогоняли — ПДн).
- Жёсткие отказы: несколько домов, финансы (платежи/прибыль), частичные совпадения.

## Чего не умеет
- Без выбранного объекта (поле «проект» пусто, в вопросе нет слова «Переделкино») —
  все 11 эталонных вопросов дают «частичные совпадения» (0 ответов).
- «кв.м», «погонный метр» не распознаются как единица → подставляется чужая строка (1 000 / 5 000).
- Вопрос без слов «стоимость/цена/сколько стоит» («ставка», «за погонный метр?») не идёт в ставки.
- Нет понятия «конфликт версий»: числа двух актов идут подряд без пометки.
- «Что обещали клиенту», «чего ждём от поставщика» → some_terms → отказ: по переписке
  нет ни поиска по смыслу, ни выборки обещаний/ожиданий; задачи из чатов не проверены.
- Ставка без дома при выбранном проекте — отвечает по всем домам вместо отказа.

## Доступ для агента
Штатный путь только через секрет `/etc/smart-core/access-token` (root:root 640) и запись
задачи в `tasks.sqlite`. В B26 не использовали: логика вызвана в отдельном процессе с
базой `mode=ro`, без токенов и без модели (на пути ставок модель не участвует).
Для регулярного eval нужен отдельный read-only токен «eval» или `GET /api/ask` с
отдельным ключом — решение Ильи (см. summary).
