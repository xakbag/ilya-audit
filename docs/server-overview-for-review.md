# ILYA CORE — структура домашнего «умного сервера» и текущие проблемы
Состояние на 03.10.2026. Документ очищен: без паролей, ключей, адресов, имён и переписок клиентов. Цель — внешняя оценка и предложения.

## 1. Железо и среда
- Домашний ПК с Windows 10 Pro, 32 ГБ ОЗУ, GPU 16 ГБ VRAM. Windows нужна и детям (Minecraft, браузер), поэтому GPU и память общие с играми.
- Внутри Windows — WSL2 Ubuntu 24.04, там живёт почти всё. Лимит WSL 14 ГБ (было 24 ГБ, из-за файлового кэша Windows голодала), `autoMemoryReclaim=gradual`.
- Доступ: Tailscale (приватная сеть), SSH; часть публикуется наружу через Tailscale Funnel (доска мониторинга) и обычный хостинг (сайты).
- Автозапуск после перезагрузки без входа владельца: задачи Планировщика Windows (boot / keepalive / presence).

## 2. Контуры (что делает сервер)
1. **Core** — ответы по документам и перепискам владельца с источником. Сейчас слабое место (см. §4).
2. **Шлюз локального ИИ** (`local_ai_gateway`) — очередь задач (суммаризация сообщений, извлечение сущностей и др.) → локальная Ollama на GPU. Решено переводить часть операций на внешний бесплатный шлюз FreeLLMAPI по белому списку, с санитайзером данных.
3. **Контроллер моделей** (`smart-model-controller`) — режимы LIGHT / HEAVY по свободной памяти Windows и присутствию человека; HEAVY ночью 23:00–10:00.
4. **Контур качества (QA)** — задачи на проверку → outbox → мост (таймер 5 мин) → внешний ревьюер/исполнитель.
5. **Исполнитель заданий** (`assignment-executor`/`supervisor`/`coordinator-watcher`) — выдаёт и контролирует задания агентам.
6. **Бизнес-контур** — мессенджеры, воркеры (partner, sender, normalizer), только черновики, отправка клиентам после ручного одобрения.
7. **Docker в WSL** — n8n и FreeLLMAPI (контейнеры); бизнес-воркеры — systemd-службы.
8. **Бэкапы** — restic локально (таймер 04:45, 29 SQLite-баз через snapshot) + шифрованная копия (rclone crypt) на облачный диск (05:30); есть проверка восстановления.
9. **Мониторинг** — коллектор (раз в минуту) → status.json → публичная под паролем доска, 12 карточек; почасовой аудит (скрипт без LLM); алерты в Telegram (пока dry-run).
10. **Сайты/проекты на хостинге** — «Дом 2» (учёт задач стройки, роли admin/viewer, фото, голосовой ввод), два сайта компании (SEO/Директ-подготовка).
11. **Агентная разработка** — Claude Code плюс «исполнитель на API» (длинные задачи), FreeLLMAPI для черновиков.
12. **Конфиги в Git** — приватный репозиторий конфигурации, проверка секретов перед коммитом.

## 3. Целевая архитектура (ещё не построена)
Детерминированный оркестратор без LLM (состояния queued→leased→started→completed|failed|blocked|dead, причина blocked обязательна, выключатель по исполнителю) — локально готов, 21/21 тестов, на сервер не выкатывался. Исполнители как сменные адаптеры: скрипты → Ollama → FreeLLMAPI → платный (запрещён без решения). Режимы Игра/День/Ночь. Таблица ставок + SQL для числовых вопросов, FTS5 + гибридный поиск для текстовых.

## 4. Текущие проблемы (факты, проверено чтением)
| # | Проблема | Влияние | Статус |
|---|---|---|---|
| 1 | Core даёт неверные ответы по ставкам: на эталоне из 17 вопросов 41% верно; ни разу не назвал конфликт версий документов; «кв.м/погонный» путает со штуками; без объекта называет цену. Прототип на таблице ставок — 100% | главный продукт ненадёжен | Решение есть, нужно «да» на подключение (P0) |
| 2 | Режим HEAVY не включается днём: свободно ~4 ГБ Windows при пороге 8 ГБ; ночью HEAVY раньше было 0,2% времени | тяжёлые задачи почти не идут | Частично: WSL урезан до 14 ГБ, HEAVY вручную пошёл (~17 задач/мин) |
| 3 | Очередь шлюза ранее стояла 140/0 без указанной причины | непрозрачность | Причина теперь пишется (`mode_reason`); очередь 0 после ручного HEAVY |
| 4 | QA: метка `empty_queue`, когда 4–5 задач ждут внешнего ревьюера; исполнитель отключён | ложная картина «всё пусто» | Подтверждено, исправляется оркестратором |
| 5 | Служба `smart-quality30` падала в start-limit от внешних запусков | шум в failed | Переведена в oneshot+disabled |
| 6 | `ilya-business-sender` срабатывает ежеминутно при «выключен» | лишняя нагрузка | Подтверждено, не критично |
| 7 | Доска ранее была открыта в интернет без пароля; сейчас закрыта Basic-входом, но найден тестовый логин со слабым паролем в `.htpasswd` | риск доступа | Нужно решение убрать |
| 8 | Токены в копиях бэкапа открытым текстом; в юнитах инлайн-токенов нет (LoadCredential) | риск при утечке копии | Копия шифруется; дальше — проверка |
| 9 | Файл с ключами внешней копии лежит на диске, не в менеджере паролей | риск | Ждёт действия владельца |
| 10 | Docker-контейнер FreeLLMAPI без лимита памяти, root, net=host | риск памяти/безопасности | План этапа 1 (лимит 512 МБ), нужно «да» |
| 11 | Оркестратор, почасовой аудит (частично), режим Игра, шлюз→FreeLLMAPI (shadow) готовы локально, не выкачены | прогресс не доехал до сервера | Ждёт «да» и окна |
| 12 | «Дом 2»: версия с ролями/фото готова, не выложена (нужен вход в панель хостинга); у новых объектов 0 задач | Дом 2 без разграничения доступа | Идёт доработка |
| 13 | Сайт-1 компании: форма не отправляет заявки, нет Метрики, нет страниц контактов/доставки; сайт-2: дубли www/index | потеря заявок и SEO | Аудит готов, правки не сделаны |
| 14 | Нестабильность: частые обрывы API-исполнителя (ECONNRESET/524 шлюза) на длинных задачах | потеря стоимости и времени | Обход: мелкие задачи, перезапуск |
| 15 | Нет мониторинга «по результату»: «служба active» ≠ «работа идёт»; для Core статус unknown | слепые зоны | Карточки «время последнего полезного результата» частично есть |

Опровергнуты гипотезы: n8n-guard охраняет несуществующий n8n (n8n жив); автообновления перезапускают службы; ответы клиентам уходят автоматически (нет, только черновики и ручное одобрение); блокировки SQLite (0 за 7 дней).

## 5. Ограничения
Только чтение без «да» владельца на изменения; секреты/ПДн не покидают машину; платные исполнители запрещены без решения; GPU делится с играми детей; бюджет памяти Windows ~4 ГБ свободно.

3. Как поднять точность Core (таблица фактов + SQL, FTS5 + эмбеддинги, пометка конфликтов версий и честное «не знаю»), чем оценивать.
