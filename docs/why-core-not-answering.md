# Почему «умный сервер» (Core) не отвечает на вопросы
Состояние на 03.10.2026. Очищено: без паролей, адресов, имён клиентов и текстов переписок. Это объяснение для внешней оценки.

## Симптом
Владелец задаёт вопрос в Core (например: «сколько стоит укладка террасной доски на доме 10 за м²?») и получает не ответ, а отказ («найдены только частичные совпадения») либо неверный/смешанный ответ. Работающим «умным» сервер пока не является.

## Как вопрос идёт к ответу
Вопрос → Core (веб-сервис, очередь задач в SQLite) → определение объекта и дома по ключевым словам → сервис знаний:
1. несколько домов в вопросе → просит уточнить;
2. договоры (цена, стороны) — прямое чтение;
3. ставки из актов (xls/xlsx) — разбор колонок «м²/м³», этаж, «комплексная строка»;
4. иначе полнотекстовый поиск FTS5 (около 259 тыс. фрагментов, 6,5 тыс. документов): если найдены все слова вопроса — локальная модель через шлюз формулирует ответ с проверкой цитат; если только часть слов (`some_terms`) — Core подменяет ответ отказом «частичные совпадения».
Результат записывается обратно в очередь задач.

## Причины (по убыванию значимости)
**Факт 1 — дефект разбора вопроса и ставок (главная причина).** Прогон 03.10 без обращения к модели (по утверждению отчёта) на 17 эталонных вопросах по реальным ставкам:
- ответы существуют на 9 вопросов — верно 0 из 9;
- отказ нужен на 8 вопросов — отказ верен в 7 (но причина всегда одна: «частичные совпадения», а не осознанное «данных нет»);
- общий результат 7 из 17 (41%).
Конкретно: ставка выдаётся только при формулировке «сколько стоит … м²»; «кв.м» не понимается, «погонный метр» подменяется штуками (1000/5000 шт вместо руб/м), вопросы про брусчатку, кровлю, плиту, основания дают отказ, хотя ставки в актах есть; конфликт двух версий (3500 и 4000 руб/м², два акта от 26.08) ни разу не назван; без указания объекта Core отвечает «4000», смешав разные дома и единицы.

**Факт 2 — нет единой таблицы ставок.** Ставки вытаскиваются из актов «на лету» эвристиками. Отдельная таблица (1607 ставок с объектом, работой, единицей, документом и датой) и прототип маршрутизатора `rates.py` собраны только что: на новом наборе 17/17, но набор писали после ошибок, и независимая слепая проверка (30 новых вопросов) только начата. В Core прототип пока не подключён.

**Гипотеза 3 — модель не всегда доступна.** Ветка «все слова найдены → локальная модель» зависит от шлюза локального ИИ и режима LIGHT/HEAVY. Днём свободной памяти Windows около 4 ГБ при пороге 8 ГБ, тяжёлый режим не включается; ранее очередь шлюза стояла 140/0. Для вопросов, идущих через модель, это даёт «нет ответа» или долгий ответ. Не подтверждено прогоном именно по этому вопросу.

**Факт 4 — нет мониторинга «по результату».** Службы показывают «active», хотя полезного ответа нет; статус Core на доске — «unknown». Поэтому деградацию заметили по ручному эталонному набору, а не по алерту.

## Что уже сделано / в работе
- Эталонный набор переписан под реальные данные; для Core измерено 41%.
- Прототип маршрута ставок и независимый слепой набор (30 вопросов); подключение к Core — за флагом, выключенным по умолчанию, с откатом (в работе).
- Далее: исправление алиасов единиц, показ обеих версий при конфликте с источниками, отказ «данных нет» вместо «частичных совпадений».
